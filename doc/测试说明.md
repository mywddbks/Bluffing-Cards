# 唬牌前端测试说明

## 1. 测试策略

前端采用三层验证：

1. **纯逻辑单测**：牌组、规则引擎、机器人、协议、网络客户端、JSON 示例；使用 Node 原生 `node:test`，无第三方依赖。
2. **浏览器冒烟**：Chrome headless 打开首页、2 人/3 人本地对局、选牌/确认、揭牌、结算、历史、规则、设置、移动端；检查 console。
3. **手工验收**：真人操作完整流程，观察信息隐藏、按钮状态和异常提示。

联机后端尚未实现，因此网络部分用 FakeWebSocket 和示例 JSON 验证契约；等 C++ 后端就绪后按 [`联调指南.md`](联调指南.md) 做双浏览器验收。

## 2. 运行方式

```bash
npm test
```

等价于：

```bash
node tests/cards.test.js
node tests/engine.test.js
node tests/bots.test.js
node tests/protocol.test.js
node tests/net-client.test.js
node tests/examples.test.js
```

> 在部分受限 Windows 沙箱中，`node --test` 的测试运行器会因 `spawn EPERM` 失败；上面的直接运行方式不经过测试运行器，已验证可用。普通开发机没有该限制。

## 4. 规则引擎重点用例

| 场景 | 断言 |
| --- | --- |
| 初始发牌 | 2 人各 27 张、3 人各 18 张；首轮先手确定 |
| 先手 | `mustPlay=true`；过牌/揭牌被拒绝 |
| 宣称数量 | 数量不等于牌数返回 `CLAIM_COUNT_MISMATCH` |
| 牌不在手中 | 返回 `CARD_NOT_IN_HAND` |
| 揭牌成功 | 质疑者收牌；下一轮质疑者下一位领出 |
| 揭牌失败 | 被质疑者收牌；下一轮被质疑者下一位领出 |
| 两轮过牌 | 所有 active 两次过牌后弃牌、下一轮最后出牌者下一位领出 |
| 最终确认重置 | 有人出牌后 `passCount` 全部归零 |
| 出完最后一张 | 进入 pending；2P 当轮结算锁名并结束 |
| 3P 锁名 | 第 1 名后继续，第 2 名后结束，剩余自动第 3 |
| pending 被揭牌说谎 | 收牌后回到 active，重新参与轮转 |
| 视图脱敏 | 其他玩家无 hand；lastPlay 无 cards；只有 reveal 带牌 |

## 7. 已知限制

- 未覆盖真实 C++ 后端；网络契约由 FakeWebSocket 和示例验证。
- 未做自动化 UI 快照/端到端测试；浏览器验证为脚本驱动 + 人工查看截图。
- 未实现断线重连、超时、语音、滑动拖选，因此没有对应测试。
- 本地 mock Bot 只保证合法和可终止，不保证策略强度；正式 AI 由后端负责。
- `.probe/` 下的脚本是开发期临时验证工具，不属于交付代码，可删除。

## 8. 新增测试建议

- 后端完成后，在 `tests/` 增加真实 HTTP/WS 集成测试（可用 Node 内置 `fetch`/`WebSocket` 或独立脚本）。

- 为 `rematch`、`leave`、`addAI`、`removeAI` 增加等待房间状态测试。
- 为移动端增加 Playwright/CDP 自动截图回归（当前环境未安装 Playwright）。
