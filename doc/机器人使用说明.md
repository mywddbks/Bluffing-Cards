# 机器人使用说明

本文档说明人机对战 AI（`static/js/game/mock/bots.js`）的使用方法、接口约定、性格调参与移植要求。模块内部结构与决策框架见 [`程序设计.md`](程序设计.md) 第 5 节，规则基线见 [`游戏规则.md`](游戏规则.md)。

## 1. 文件位置与依赖

```text
static/js/game/mock/bots.js     机器人逻辑（本文档对象）
static/js/game/cards.js         唯一依赖：isWild、RANKS
static/js/game/mock/engine.js   对局引擎，产出 GameView
static/js/game/mock/client.js   本地人机客户端，自动调度机器人
```

零第三方依赖，浏览器 ES Modules 与 Node.js（20+）均可直接运行。

## 2. 对外接口

### 2.1 chooseBotAction(view, rng)

机器人的唯一决策入口。

```js
import { chooseBotAction } from "./bots.js";

const action = chooseBotAction(view, rng);   // action 或 null
```

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `view` | GameView | **该机器人自己的**视图，即 `getView(state, botPlayerId)` 的返回值。禁止传入内部 state 或其他玩家的视图。 |
| `rng` | `() => number` | 随机源，必须返回 `[0, 1)`。可省略（默认 `Math.random`）；测试时用 `makeRng(seed)` 注入以复现牌局。 |

返回值：

- `null`：当前不是该机器人的回合（三个动作均不可用）。
- 一个合法动作对象，三种之一：

```js
{ type: "play",      payload: { cards: ["S-7", "J-BJ"], claim: { rank: "7", count: 2 } } }
{ type: "challenge", payload: { targetPlayerId: "p2" } }
{ type: "pass",      payload: {} }
```

动作保证落在 `view.you.actions` 允许范围内；内部任何策略分支异常时都有「过牌 / 保底出牌」回退，轮到就一定能动。

### 2.2 PERSONA（具名导出）

三种性格的参数表，可整体读出用于配置或对照测试：

```js
import { PERSONA } from "./bots.js";
// PERSONA.steady / PERSONA.balanced / PERSONA.bluffer
```

性格通过 `createGame` 的玩家配置传入，视图会原样带出：

```js
createGame({
  players: [
    { playerId: "you", seat: 0, name: "你" },
    { playerId: "ai-1", seat: 1, name: "阿稳", isAI: true, persona: "steady" }
  ],
  maxPlayers: 2
});
```

未指定 `persona` 时按 `balanced` 处理。

## 3. 性格参数调优

每个性格 5 个参数，含义与调整方向：

| 参数 | 作用 | 调大后的行为 |
| --- | --- | --- |
| `bluffAppetite` | 有真牌可出时仍掺假的意愿 | 更爱说谎，出牌更快但更易被揭牌 |
| `challengeEdge` | 质疑所需的额外安全边际（期望收益门槛） | 更"信邪"，几乎不主动揭牌 |
| `riskAversion` | 被时代价的放大系数（影响掺假打分） | 更怕被抓，倾向出真牌 |
| `finalPass` | 最终确认阶段过牌（弃牌堆）概率 | 更常熬到弃牌，适合守牌型打法 |
| `leaderTrust` | 对"先手自选牌面属实"的信任度 | 更少质疑先手的第一手牌 |

预置值：`steady` 少诈多守、`balanced` 居中、`bluffer` 激进诈牌且爱赌质疑。新增性格只需在 `PERSONA` 中加一组参数并在使用处传名。

## 4. 运行方式

### 4.1 浏览器体验（无需后端）

```bash
node tools/serve.mjs      # 打开 http://localhost:8080
```

首页「快速人机 · 2 人 / 3 人」即由本机器人扮演对手：`MockClient._scheduleBots` 在轮到 AI 时取该 AI 自己的视图调用 `chooseBotAction`，延迟 620~1250ms 模拟思考。

### 4.2 单元测试

```bash
node tests/bots.test.js
```

覆盖两条不变量：

1. 全机器人对局只从自己的视图行动、动作全部合法、必然终局（不活锁）；
2. 非回合玩家返回 `null`。

多随机种子、2/3 人局的稳健性验证：修改 `tests/bots.test.js` 中的 seed 重复运行即可。

## 5. 移植到正式后端（C++ AI）

正式 AI 由后端实现时，本模块即参考实现，移植要点：

1. **输入契约**：只允许喂 `GameView` 级信息——自己的手牌、各家剩余张数、当前宣称牌面、牌堆数量、过牌计数、公开历史（含 `reveal` 的实际牌）。视图不含他人手牌与未揭牌的出牌内容，移植后也不得从其他渠道补齐。
2. **输出契约**：动作 JSON 与第 2.1 节三种形态一致，可直接按 [`api.md`](api.md) 的 `play` / `challenge` / `pass` 信封提交给自家裁判。
3. **随机性**：服务端应每回合注入独立随机源，保证同种子可复现，便于 AI 对拍与验收。
4. **调度**：后端在 `state` 下发后判断 `turn` 是否为 AI 座位，是则调用 AI 并以 `actionId` 幂等提交，语义与 `MockClient` 相同。

## 6. 已知边界

- 机器人不实现超时托管、悔棋与多人观战；这些属于后端职责。
- 谎话概率基于公开信息的启发式推算（牌面供应 + 行为信号），不保证纳什均衡；对纯随机对手表现良好，对同样带读牌逻辑的 AI 对战时风格参数可能需要重调。
- 本地 mock 机器人同时用于前端演示与课程人机；若课程后续要求"前端演示与正式 AI 分离"，可复制本文件为 `ai/` 独立模块，接口无需改动。
