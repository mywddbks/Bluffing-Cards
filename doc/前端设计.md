# 唬牌前端设计

## 1. 目标与约束

- **零构建**：不引入打包器、框架或第三方运行时；浏览器直接加载 ES Modules。
- **两种模式共用一套 UI**：
  - 本地 mock：纯浏览器规则引擎 + 演示机器人，无后端也能完整游玩；
  - 联机：REST 建房/加入 + WebSocket 接收服务端权威视图。
- **服务端权威**：前端不判定揭牌真伪、胜负、名次，不广播任何未公开手牌。
- **素材自绘**：54 张牌面、牌背、图标和音效全部由 CSS/SVG/WebAudio 生成，不依赖外部图片、字体或 CDN。
- **中文优先**，桌面、平板、手机均可操作。

## 2. 代码结构

```text
static/
  index.html            唯一 HTML；只放 #app / #modal-root / #toast-root
  css/
    tokens.css          颜色、字号、间距、牌尺寸、断点
    base.css            reset、背景、焦点、减少动画
    layout.css          首页/大厅/页头布局
    components.css      按钮、徽章、表单、弹窗、Toast、抽屉
    cards.css           牌面、牌背、手牌、牌堆
    table.css           牌桌、座位、中央区、操作栏
    screens.css         结算、错误页、翻牌
    responsive.css      1024 / 600 / 380 断点
  js/
    main.js             装配、store、屏幕切换、连接生命周期
    config.js           apiBase/wsPath；window.__BLUFF_CONFIG__
    strings.js          中文文案、历史事件描述、错误映射
    session.js          会话与昵称的 localStorage
    store.js            极简发布订阅
    router.js           URL 房间码
    game/
      cards.js          牌组、排序、标签、随机数
      mock/engine.js    纯规则引擎（服务端语义参考实现）
      mock/bots.js      演示机器人（只读自己的 GameView）
      mock/client.js    与 NetworkClient 同接口的本地客户端
    net/
      protocol.js       协议版本、actionId、动作信封、关闭码
      ws-client.js      WebSocket 包装（可注入 FakeWebSocket）
      client.js         REST + NetworkClient
      errors.js         ApiError / NetworkError
    ui/
      dom.js            h()/button() 等 DOM 工具
      cards.js          牌面/手牌/微型牌堆 DOM
      home.js           首页、创建/加入房间弹窗
      lobby.js          等待房间
      table.js          牌桌、手牌选择、牌面选择、操作栏
      result.js         结算领奖台
      history.js        历史抽屉
      reveal.js         揭牌结果
      modals.js         通用弹窗/确认框/焦点陷阱
      rules.js          规则弹窗
      settings.js       音效/减少动画
      sound.js          WebAudio 合成音效
      toast.js          轻提示
```

没有单独创建 `view-model.js`；视图直接使用后端 `GameView`。没有单独创建 `ui/seat.js`、`ui/hand.js`，座位与手牌在 `table.js` 内组合。

## 3. 数据流

```text
用户点击
  -> ui 构造动作 {type,payload}
  -> GameClient.send(type,payload)
      - MockClient: 本地 engine.applyAction，生成新 view/events
      - NetworkClient: buildActionEnvelope -> WebSocket
  -> onState({view,events})
  -> main.handleState：按 view.phase 切换 lobby/table/result
  -> 对应 render 函数重建屏幕
  -> events 中的 reveal 打开揭牌弹窗
```

`GameClient` 的共同接口：

```js
client.mode                 // "mock" | "network"
client.connect()            // Promise
client.send(type, payload)  // 返回 actionId 或 null
client.onState({view, events})
client.onError(error)
client.onClose(info)
client.close()
```

联机动作信封：

```json
{
  "v": 1,
  "type": "play",
  "actionId": "uuid",
  "baseSeq": 42,
  "payload": { "cards": ["S-7"], "claim": { "rank": "7", "count": 1 } }
}
```

`baseSeq` 是客户端最后收到的服务端 `state.seq`；服务端据此拒绝过期动作。`actionId` 用于幂等去重。

## 4. 屏幕与关键交互

### 首页

- 昵称输入（localStorage 记忆）、快速人机 2/3 人、创建联机房间、加入房间、规则、设置。
- URL 带 `?room=CODE` 时预填房间码。
- 创建/加入弹窗内处理异步 loading 与错误，不关闭弹窗。

### 等待房间

- 按座位显示真人/AI、房主、准备状态；房主可复制房间码、添加/移除 AI、开始牌局。
- 所有真人准备、座位坐满后，房主才能开始。
- AI 由房主添加，演示机器人目前有三种性格：`steady` / `balanced` / `bluffer`。

### 牌桌

- 1 或 2 个对手座位，显示剩余张数、过牌 pip、待确认/锁定/轮次标记。
- 中央显示本轮宣称牌面、累积牌堆、最后出牌者、最终确认横幅、轮到谁。
- 自己的手牌点击多选；数量自动统计，不手输。
- 先手第一次出牌：A～K 快捷牌面选择，确认弹窗中再次确认“N 张 X”，确认后牌面锁定。
- 跟牌：牌面锁定，只能选本轮牌面；按钮文案为“出牌 / 跟牌 · 宣称 N 张 X”。
- 揭牌：按钮显示目标与宣称，例如“揭牌 阿稳：2 张 7”；没有最后出牌组或目标是自己时禁用。
- 过牌：普通阶段显示“暂过”；最终确认阶段显示“最终确认过牌”并二次确认；2 人局最后一张不匹配时显示“保留最后一张（过牌）”的说明。
- 待确认/已锁定玩家不能操作；错误提示不清空当前选牌（非法出牌可调整后再试）。
- 顶部“记录”打开右侧/移动端全屏历史抽屉；历史不展示未揭牌的牌面。

### 揭牌与结算

- 揭牌弹窗只展示被查的那一组实际牌、宣称、真伪和收牌者。
- 结算页领奖台显示第 1/2/3 名、结束原因；房主可“再来一局”，其他玩家返回首页。
- 联机 `rematch` 由房主发起；本地 mock 重新发牌。

## 5. 响应式与可访问性

- 断点：1024px（紧凑牌桌）、600px（手机单列、底部操作栏）、380px（更小字号与间距）。
- 手牌用 `layoutHand` 计算 `--hand-step`：桌面尽量展开，27 张时自动压缩，手机设置最小步长并允许横向滚动。
- 操作按钮在手机上保持 3 列，使用 `minmax(0,1fr)` 防止长文案撑破布局。
- 手牌列表使用 `role="listbox"`、`aria-multiselectable`；点数选择使用 radiogroup；弹窗有焦点陷阱、Escape 关闭和焦点恢复。
- 支持 `prefers-reduced-motion` 与设置里的“减少动画”；音效可关闭，WebAudio 首次交互后才创建。
- 所有牌都有中文 `aria-label`（如“红桃 A”“小王”）。

## 6. 安全与信息隐藏

- 前端从不根据本地数据推断联机结果；`GameView` 是唯一数据源。
- `players[]` 不含 `hand`；`round.lastPlay` 不含 `cards`；`round.pile` 不出现；`history` 中只有 `reveal` 事件带牌。
- 联机会话 `playerToken` 只存在内存和 localStorage，不进入视图、不打印。
- 本地 mock 的机器人只拿到自己的 `getView`，不读取其他玩家手牌；它只是演示 AI，不是正式课程 AI。

## 7. 已知限制与二期

- 不自动重连；刷新回到首页。协议保留 `playerToken`/`sync`，后端可自行扩展。
- 不做发牌/收牌动画、滑动拖选、语音、旁观、聊天、排行榜。
- 不实现服务端超时；如后端增加计时，需在 `YouActions` 和 UI 中补充倒计时展示。
- 只有 2～3 人；不支持 4 人以上或换座。
- `static/style.css` 是旧占位文件，页面未引用；受工作区 ACL 影响暂未删除，可安全忽略。
